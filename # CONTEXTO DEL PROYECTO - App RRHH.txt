# CONTEXTO DEL PROYECTO - App RRHH Movilsat

## 📋 Descripción General
Sistema de gestión de Recursos Humanos para Movilsat Comunicaciones SA con:
- Portal de empleados (recibos de sueldo, firma digital, adelantos, vacaciones)
- Panel de administración (carga de recibos, gestión de empleados, reportes)
- Backend Python para extracción de datos de PDFs
- Base de datos Supabase

## 🏗️ Arquitectura

### Frontend
- **Framework:** Next.js 16.2.7 con Turbopack
- **Lenguaje:** TypeScript
- **UI:** Tailwind CSS
- **Autenticación:** Supabase Auth
- **Rutas principales:**
  - `/admin/*` - Panel de administración
  - `/empleado/*` - Portal del empleado
  - `/api/*` - Endpoints de API

### Backend Python
- **Framework:** FastAPI
- **Ubicación:** `C:\Users\Usuario\backend-extractor`
- **Puerto:** 8000
- **Función principal:** Extraer datos de PDFs de recibos de sueldo
- **Endpoint:** `POST /extraer-lote-recibos`

### Base de Datos
- **Proveedor:** Supabase (PostgreSQL)
- **Tablas principales:**
  - `empleados` - Datos de empleados
  - `recibos_sueldo` - Recibos de sueldo
  - `solicitudes_sueldo` - Adelantos/préstamos
  - `vacaciones` - Control de vacaciones
  - `notificaciones` - Notificaciones push

🔄 Flujo de Carga de Recibos
Admin sube PDF(s) desde /admin/cargar-recibos
Archivos se suben a Supabase Storage (bucket: recibos-originales)
Se envían al backend Python vía /api/admin/procesar-recibo-url
Backend extrae datos de cada página/recibo
Next.js procesa los datos y crea empleados si no existen
Se guardan en BD con upsert (evita duplicados)
Cada empleado recibe su recibo individual
🔐 Autenticación
Admin
Login: /admin/login
Credenciales: Email/password de Supabase
Rol: 'admin' en tabla empleados
Empleado
Login: Automático vía localStorage (empleado_id)
Datos: Se guardan en localStorage.getItem('empleado_data')
Acceso: Solo a sus propios datos
📝 Firma Digital
Ley: 17250 (Argentina)
Flujo:
Empleado firma en canvas (FirmaDigital.tsx)
Se convierte a base64
Se envía a /api/recibos/firmar
Se valida que no haya recibos anteriores pendientes
Se guarda firma + hash SHA-256
Se actualiza estado y estado_firma a 'firmado'

SQL - Ver últimos recibos cargados
SELECT 
  id,
  empleados.nombre_completo,
  periodo,
  quincena,
  tipo_recibo,
  pagina_recibo,
  SUBSTRING(pdf_original_url FROM 1 FOR 100) as url
FROM recibos_sueldo
ORDER BY created_at DESC
LIMIT 10;

Notas Importantes
Período forzado: Al cargar recibos, se puede especificar manualmente el período (YYYY-MM)
Zonas/Plantas: Mar del Plata, Mendoza, Moreno, San Juan (campo opcional en carga)
Duplicados: El sistema usa upsert con conflicto en (empleado_id, periodo, quincena, tipo_recibo)
Firma secuencial: No se puede firmar un recibo si hay anteriores pendientes
Anulación: Solo se puede anular dentro de las 24hs de firmado
